# Security Rules

- Treat credentials, tokens, private keys, and sensitive user or project data as confidential.
- Do not expose secrets in source code, logs, examples, reports, or handoffs.
- Validate untrusted input at trust boundaries and use established safe APIs.
- Apply least privilege to tools, accounts, data access, and execution.
- Consider authentication, authorization, data exposure, dependency, and supply-chain risks when relevant.
- Report security findings clearly, with impact and evidence appropriate to the audience.
- Escalate suspected exposure, exploitation, or material security risk promptly; do not conceal or silently accept it.
- Require independent security review for changes classified as high risk by the project or approval policy.
