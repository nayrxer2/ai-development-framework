# Global Rules

These rules apply across framework roles unless a more specific, compatible project requirement adds detail.

1. Follow the active task's acceptance criteria and applicable project instructions.
2. Preserve existing behavior unless a change is explicitly intended.
3. Keep changes scoped, explain important trade-offs, and make uncertainty visible.
4. Follow repository conventions and prefer clear, maintainable implementations.
5. Preserve type safety, handle errors explicitly, and avoid unrelated refactors.
6. Validate work using checks appropriate to the changed behavior and report their results accurately.
7. Add or update tests for behavior changes where the project supports them.
8. Do not claim a check, review, or action was completed without evidence.
9. Protect private data, credentials, and other sensitive information.
10. Prefer clear ownership, explicit handoffs, and durable records for significant decisions.
11. Load only the governance and skill guidance relevant to the task.
12. Follow [`SECURITY_RULES.md`](SECURITY_RULES.md) for security-sensitive work and [`APPROVAL_POLICY.md`](APPROVAL_POLICY.md) for decisions requiring approval.
13. When requirements conflict, preserve mandatory safety, privacy, security, and platform constraints; surface unresolved ambiguity rather than silently choosing.
